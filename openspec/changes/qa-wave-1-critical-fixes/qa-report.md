## Notes

- **QA fixes (after run, 2026-10-29):** three bugs found by this QA were fixed: the pairing code was regenerated after "Volver" (`b51522c`), the navigation bar stayed visible after the keyboard closed on API 26 (`efe9df7`), and the server answers `409` instead of `400` for an out-of-stock product, so the cart showed the generic error (CAR-023, `a7ecf1d`).
- **Contract gap (backend):** `POST /carts/share-pdf` (and probably `POST /orders`) answers `409 {"errorCode":"PRODUCT_NOT_SELLABLE","productId":…,"productName":…,"reason":"OUT_OF_STOCK"}` for a product that cannot be sold. It is not in `docs/android/api-contract.md` (checked against the version updated on 2026-10-29, phases 29–34): both endpoints still list `400 BAD_REQUEST` for an inactive or not-`AVAILABLE` product. The app accepts both `400` and `409` and does not read the body (the recheck finds the line itself); the contract should document it.
- **Session id in logs:** the pairing `sessionId` appears in the logged WebSocket URL and in the `pairing-token` response. With it, anyone can exchange the device token once the code is approved. It is not in the D10 field list; it could be added to the redaction list (`sessionId`, plus URL masking) in a follow-up. Evidence files mask it.
- **Settings gate on `Medium_Tablet`:** the AJU-011 run locked it; the staff PIN change lifted it the same evening (11.4).

- **Baseline APK:** `main` @ `f8622dd`, `profile`, installed over the existing debug build so the pairing was kept. After the 1.1 spike, the clean `main` APK was rebuilt and reinstalled.
- **Kiosk state on the API 26 emulator:** `kioskMode` is on (the side menu shows "Salir del modo kiosko"), and no exit PIN is set.
- **Extra finding (1.1):** the shell seeds `kioskLock` with `INACTIVE`, so every cold start while pinned calls `stopLockTask()` and then asks to pin again. This is added to D8 / task 6.0.
- **Extra finding (1.2):** the API error body uses `errorCode` (for example `"errorCode":"VALIDATION_ERROR"`), not `code`. The error parsing in tasks 4.4 and 5.2 must read `errorCode`.
- **Seen in passing (wave 2):** CAR-031: the cart "Compartir" button looks enabled with an empty form.
